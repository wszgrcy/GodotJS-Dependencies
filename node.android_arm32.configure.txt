# Node.js configure arguments: Android arm32 / armv7 (builds libnode for android.arm32)

# Cross build: ./configure only knows *what* to target, the compiler comes from the
# environment, which is all gyp reads (tools/gyp ninja.py):
#   CC_target, CXX_target, AR_target, NM_target, READELF_target
# For this target those are the NDK wrappers
#   $NDK/toolchains/llvm/prebuilt/<host>/bin/armv7a-linux-androideabi<api>-clang[-++]
# prepare_node_build.sh refuses to continue when they are missing.

# Node's own helper is ./android-configure <NDK path> <API level> <arch>, at the
# source root in 26.13.1 (android-configure plus android_configure.py). It exports
# CC/CXX to the NDK wrappers, puts the NDK bin on PATH, sets GYP_DEFINES, and then
# runs ./configure with --dest-os=android --openssl-no-asm --cross-compiling. Passing
# the variables yourself and calling ./configure does the same thing, which is what
# CI does here (gyp reads CC_target first, then CC).

# --cross-compiling forces the host/target toolset split; Node infers it from the CPU
# alone, so an arm target would get it anyway. --openssl-no-asm matches
# ./android-configure: OpenSSL's asm configs are not generated for android targets.

# When --dest-os=android and --dest-cpu=arm are combined, configure.py forces
# arm_version 7 and arm_fpu vfpv3 (it does that itself, around the
# "if options.dest_os == 'android'" line in configure.py), so there is nothing to
# pass here for the FPU.

# This target is NOT in the build matrix, and it is not a matter of nobody having
# tried it: V8 refuses to be built for 32-bit ARM from a 64-bit machine. The first V8
# object compiled with -DV8_TARGET_ARCH_ARM stops at
#   deps/v8/include/v8config.h: error: Target architecture arm is only supported on
#   arm and ia32 host
# which is a check on the machine doing the build, not on the NDK: the arm simulator V8
# uses to run 32-bit ARM code on the build machine is only built for a host that is
# itself 32-bit ARM or ia32. An arm64 runner answers to neither (V8_HOST_ARCH_ARM64), so
# switching the job to an arm64 runner would not help either. Keeping an android arm32
# Node bundle therefore needs a 32-bit ARM build machine (an armv7 board, or an ia32
# container); everything in this file is what such a build would pass.
#
# Measured on linux/x64 with NDK r29: the build compiles every non-V8 object and then
# fails with that #error. GodotJS's V8-only android.arm32 bundle is unaffected, because
# that path does not build V8 for the host toolset the way Node does.
--ninja
--dest-os=android
--dest-cpu=arm
--cross-compiling
--openssl-no-asm
--with-intl=full-icu
--without-node-options
--without-npm
--disable-single-executable-application
