# Node.js configure arguments: Android arm64 (builds libnode for android.arm64)

# Cross build: ./configure only knows *what* to target, the actual compiler comes
# from the environment, which is all gyp reads (tools/gyp ninja.py):
#   CC_target, CXX_target, AR_target, NM_target, READELF_target
# With the Android NDK those are the wrapper compilers in
#   $NDK/toolchains/llvm/prebuilt/<host>/bin/
# named aarch64-linux-android<api>-clang / -clang++ (the target and API level are
# in the file name). prepare_node_build.sh refuses to continue when they are
# missing, because otherwise the build quietly produces host-architecture objects.
# The plain CC/CXX forms work too - that is the form Node's ./android-configure sets.

# Node's own helper is ./android-configure <NDK path> <API level> <arch>, at the
# source root in 26.13.1 (android-configure plus android_configure.py). It exports
# CC/CXX to those NDK wrappers, puts the NDK bin on PATH, sets GYP_DEFINES, and then
# runs ./configure with --dest-os=android --openssl-no-asm --cross-compiling. Setting
# the variables and calling ./configure, as CI does here, amounts to the same thing.
# Android is still unsupported upstream in the sense that matters: BUILDING.md says so
# and none of Node's own CI workflows build it.

# --cross-compiling forces the host/target toolset split (Node infers it from the CPU
# alone). --openssl-no-asm matches ./android-configure: OpenSSL's asm configs are not
# generated for android targets.

# API level 28 matches what the Godot Android export templates use as their
# minimum, so nothing in the engine's own dlopen set can be missing.
--ninja
--dest-os=android
--dest-cpu=arm64
--cross-compiling
--openssl-no-asm
--with-intl=full-icu
--without-node-options
--without-npm
--disable-single-executable-application
