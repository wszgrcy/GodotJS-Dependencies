# ./configure arguments for Node.js on Windows x86_64.
# See node.linux_x86_64.configure.txt for what the shared options do.
#
# ./configure has to run inside a "x64 Native Tools Command Prompt" environment
# (the jobs call vcvars64 first); it only records the toolchain, cl.exe does the
# work. Node's static build uses /MT, which is what Godot already links against,
# so nothing has to be aligned here.

--ninja
--dest-cpu=x64
# Node calls Windows "win"; naming the target keeps the file honest
# about what it cross-compiles to when a runner differs.
--dest-os=win

--with-intl=full-icu
--without-node-options
--without-npm
--disable-single-executable-application

# Node 24 and newer are built on Windows with clang-cl instead of cl.exe
# (BUILDING.md calls it a requirement), and the option carries the LLVM version:
# ./configure --clang-cl=19.1.5. A bare --clang-cl stops configure with
# "argument --clang-cl: expected one argument".
#
# The version is a property of the machine, not of this file, so the option is not
# written here: the CI job reads `clang-cl --version` - the same thing Node's own
# vcbuild.bat does - and appends --clang-cl=<version> to the arguments. Building by
# hand on Windows means adding that option yourself, with the version you have.
#
# --clang-cl only records which toolchain the build is meant for; it does not change
# the compiler ninja runs. gyp's ninja generator looks cl.exe up through the Visual
# Studio environment by itself. Actually compiling with clang-cl needs two more
# things, and the CI job adds both:
#
#   GODOTJS_NODE_CLANG_CL=<absolute path to clang-cl>   (environment variable)
#       gyp's ninja generator only switches compilers when it is handed a
#       make_global_settings CC entry ending in "clang-cl", and it requires that entry
#       to be identical in the top level of every .gyp file of the build - Node's build
#       files share no single top-level include, so node.gyp cannot carry it alone.
#       patches/godotjs-gyp-win-clang-cl.patch therefore adds a hook that reads this
#       variable (or -G clang_cl=<path>) and feeds the same code path. prepare_node_build.sh
#       stops when --dest-os=win is built without it, because the alternative is cl.exe
#       and Node 24 and newer cannot be built with cl.exe.
#       The value has to end in clang-cl with no .exe, and a space in the path is fine
#       (LLVM normally installs to C:\Program Files\LLVM\bin).
#   CXXFLAGS=/std:c++20 (and CXXFLAGS_host for the build-time tools)
#       the C++ standard. Node asks for it through msvs_settings' LanguageStandard,
#       which gyp marks as MSBuild-only, so with --ninja the compile line gets no
#       standard and each compiler's own default decides: cl.exe is C++14, which is
#       what made ICU's headers fail to parse; clang-cl is gnu++17, still short of
#       the C++20 Node and V8 need.
#
# Both spellings of the standard flag work for cl.exe; only /std: works for clang-cl
# (in clang-cl mode -std= is ignored without complaint).
